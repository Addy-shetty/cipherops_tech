How to read this

Sizes, VRAM and run commands

  • File sizes and VRAM assume a 4-bit (Q4) quantised file and a normal context window. Longer contexts need more memory.
  • No GPU? Most 7–9B models run from system RAM on a CPU, just slowly. Antares runs comfortably on a laptop.
  • Run commands use Ollama for ready-made GGUF files and vLLM for full Hugging Face weights. LM Studio and llama.cpp can load the same GGUF files.
  • Gated models (like Antares) need you to request access on Hugging Face and log in with a token before they download.
  • Benchmarks on model cards are usually the makers' own. Test any model on your own data before trusting it.
Use them safely

Dual-use tools, real responsibilities

  • Only test what you're authorised to test. Offensive models don't change the law: get written scope first.
  • Keep the box locked down. Don't expose Ollama, vLLM or Open WebUI to the internet; put them behind authentication.
  • Sandbox agents. Models that run shell commands (Antares, agentic Qwen setups) belong in a container with no network and no secrets.
  • Verify everything. Models invent CVEs, flags and file paths. Treat output as a lead, not a finding.
  • Check dates. Training data has a cut-off; pair models with current advisories for anything recent.
  • Why no "abliterated" models here? Those strip a model's safety training wholesale. The security-tuned models above already answer security questions, with clearer provenance and terms.
